Five patterns worth keeping

Use these to decide which examples deserve a closer read.

  1. 01

    Give engineers a useful asset

    Docs, manuals, methods and free tools can earn trust before the product is evaluated. Stripe, PagerDuty, Basecamp and Algolia show different versions of this.

  2. 02

    Name the work buyers already see

    A category or job title helps teams explain a new budget. Honeycomb, dbt, Humanitec and AI Engineer built audiences around a shared vocabulary.

  3. 03

    Make proof repeatable

    A benchmark or study travels further when people can check the method. Public failures and weak demos can also travel; Devin is the cautionary example.

  4. 04

    Let developer use support enterprise sales

    Individual adoption can open the account. Governance, security, procurement and services then make the purchase possible. Snyk, HashiCorp and Cursor illustrate the sequence.

  5. 05

    Design for agents and existing budgets

    Agents increasingly read docs and create free accounts. For enterprise buyers, marketplaces, systems integrators and tools already in the workflow can shorten distribution and purchasing.

Stripe: docs that run on the reader's own key, and an API that never breaks (2011 to 2022)

Why it worked

A working sample makes the docs a product trial. Version pinning gives enterprise buyers confidence that integrations will not break without warning.

What they did

Stripe personalised code samples with each reader's test key and kept accounts on dated API versions. It also made documentation an engineering responsibility.

Evidence and limits

Compatibility kept with every API version since 2011, across "almost a hundred backwards-incompatible upgrades" in six years company-reported. The career-ladder practice comes from a former Stripe docs manager, via Mintlify third-party. No traffic or conversion number exists.

OneFlux application

Let readers run the quickstart in their own sandbox with their repo filled in. Publish a pinned versioning policy for agent behaviour at launch.

Cost and sources
Cost

Not documented. The old docs platform held hundreds of pages maintained by many teams.

Tailwind: free docs selling a paid kit, and what happened when agents took the traffic (2017 to 2026)

Why it worked

Frequent docs visits made paid conversion cheap while developers still came to the site.

What they did

Tailwind used free framework docs to sell a book and paid component kit. The model weakened when AI assistants began answering questions without sending people to the docs.

Evidence and limits

Tailwind UI was "about to cross $2 million in revenue" five months after launch company-reported. In January 2026 Adam Wathan said docs traffic was down about 40% from early 2023, revenue was down close to 80%, and 75% of engineering had been let go, because AI assistants answer without sending readers to the docs company-reported.

OneFlux application

Keep docs useful, but put a route to the paid product inside OneFlux output, such as a link on a generated spec.

Cost and sources
Cost

A small team; three hired developers named in 2020 company-reported.
